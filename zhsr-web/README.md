# zhsr-web

Веб-клиент ZHSR на Quasar (Vue 3, TypeScript, Vite).

## Запуск

Нужен Node.js 22.22 или новее (24, 26).

```bash
npm install        # ставит зависимости приложения и зависимости src-pwa
npm run dev        # dev-сервер на http://localhost:9999, запросы /api проксируются на сервер zhsr-app (:8080)
npm run build      # сборка в dist/pwa
npm run typecheck  # проверка типов
npm run lint       # форматирование и ESLint
npm run test       # unit-тесты (Vitest)
npm run e2e        # e2e-тесты (Playwright)
```

## Части приложения

Приложение состоит из трёх частей. Каждая часть собирается в отдельный чанк (файл JavaScript) и загружается целиком при
первом переходе на любую её страницу. После этого переходы между страницами одной части выполняются без загрузки.

| Часть                         | Папка          | Адрес        | Чанк      | Когда загружается                                   | PWA                                               |
| ----------------------------- | -------------- | ------------ | --------- | --------------------------------------------------- | ------------------------------------------------- |
| Мобильная                     | `src/pwa/`     | `/m/...`     | `pwa`     | при открытии на телефоне                            | да: устанавливается на телефон, работает без сети |
| Десктопная (пользовательская) | `src/desktop/` | `/...`       | `desktop` | при открытии на компьютере                          | нет                                               |
| Администрирование             | `src/admin/`   | `/admin/...` | `admin`   | при первом переходе на пункт меню администрирования | нет                                               |

Администрирование — не отдельное приложение, а редко используемые пункты меню десктопной части. Страницы
администрирования показываются внутри layout десктопной части, но их код загружается только после клика по пункту меню.

Общий код всех частей (Vue, Quasar, i18n, роутер, `src/shared/`, `src/api/`) находится в стартовом бандле.

### Выбор части по устройству

Режим устройства определяется в `src/shared/device.ts` медиазапросом `(pointer: coarse) and (hover: none)`, то есть
сенсорный экран без мыши.

- На телефоне и планшете любой адрес десктопной части и администрирования перенаправляется на `/m`.
- На компьютере любой адрес мобильной части перенаправляется на `/`.
- При включении и выключении эмуляции устройства в DevTools приложение переключается между частями без перезагрузки.

Правило задано в `src/router/index.ts` и опирается на `meta.part` корневого маршрута части в `src/router/routes.ts`.

## Как добавить страницу

### В десктопную часть

1. Создайте компонент страницы в папке раздела: `src/desktop/<раздел>/<Имя>Page.vue`, например
   `src/desktop/trips/TripsPage.vue`.
2. Экспортируйте его в точке входа `src/desktop/desktop.ts`:
   ```ts
   export { default as TripsPage } from './trips/TripsPage.vue'
   ```
3. Добавьте маршрут в `children` маршрута `/` в `src/router/routes.ts`:
   ```ts
   { path: 'trips', name: 'trips', component: () => desktop().then((m) => m.TripsPage) },
   ```
4. Добавьте пункт меню в `items` файла `src/desktop/menu/menu.json`:
   ```json
   { "id": "trips", "label": "Рейсы", "icon": "trips", "route": "trips" }
   ```
   Пункт отправляет в шину событие `menu-trips`, а `DesktopLayout.vue` переходит на маршрут `route`.
5. Добавьте переводы текстов в `src/i18n/kk.json` и `en.json` (см. «Тексты и переводы»).

### В администрирование

1. Создайте компонент страницы: `src/admin/<раздел>/<Имя>Page.vue`, например `src/admin/users/UsersPage.vue`.
2. Экспортируйте его в точке входа `src/admin/admin.ts`:
   ```ts
   export { default as UsersPage } from './users/UsersPage.vue'
   ```
3. Добавьте маршрут в `children` маршрута `/` в `src/router/routes.ts` с префиксом `admin/`:
   ```ts
   { path: 'admin/users', name: 'admin-users', component: () => admin().then((m) => m.UsersPage) },
   ```
4. Добавьте пункт меню в `admin.items` файла `src/desktop/menu/menu.json`.
5. Добавьте переводы текстов в `src/i18n/kk.json` и `en.json`.

### В мобильную часть

1. Создайте компонент страницы: `src/pwa/<раздел>/<Имя>Page.vue`, например `src/pwa/checklist/ChecklistPage.vue`.
2. Экспортируйте его в точке входа `src/pwa/pwa.ts`:
   ```ts
   export { default as ChecklistPage } from './checklist/ChecklistPage.vue'
   ```
3. Добавьте маршрут в `children` маршрута `/m` в `src/router/routes.ts`:
   ```ts
   { path: 'checklist', name: 'pwa-checklist', component: () => pwa().then((m) => m.ChecklistPage) },
   ```
4. Добавьте переводы текстов в `src/i18n/kk.json` и `en.json`.

Страница, в которую «проваливаются» из списка (например, редактор маршрута `/routes/:id`), показывается на весь экран
без левого меню: у её маршрута задаётся `meta: { hideMenu: true }`.

Имена маршрутов мобильной части начинаются с `pwa-`, имена маршрутов администрирования начинаются с `admin-`.

## Фиктивные пользователи

Пока сервера нет, пользователя выбирает логин при входе (пароль — любой): `lnp` — начальник поезда, `cond` —
проводник, `pem` — ПЭМ, `master` — мастер депо, `instr` — инструктор поездных бригад, `plan` — планировщик вагонов и проводников. Без входа
на телефоне — начальник поезда, на компьютере — планировщик вагонов и проводников с ролью мастера депо (см. `src/api/session.ts`). Работу без
связи можно проверить, выключив сеть в DevTools: фиктивные вызовы API без сети падают, как настоящие.

## Правила импорта

От этих правил зависит, в какой чанк попадёт код. Нарушение правила не вызывает ошибку сборки, но меняет состав чанков.

1. **Страница подключается к маршруту только через точку входа своей части** (`pwa.ts`, `desktop.ts`, `admin.ts`) и
   динамический импорт в `routes.ts`. Если импортировать страницу напрямую (
   `import TripsPage from '@/desktop/trips/TripsPage.vue'`) в `routes.ts` или в другом общем файле, она попадёт в
   стартовый бандл и будет загружаться на телефоне.
2. **Код одной части не импортирует статически код другой части.** Например, страница десктопной части не импортирует
   компонент из `src/admin/` или `src/pwa/`. Иначе код другой части попадёт в чужой чанк или чанки начнут загружать друг
   друга.
3. **Код, нужный нескольким частям, кладётся в `src/shared/`** (компоненты в `src/shared/components/`, composables в
   `src/shared/composables/`) или в `src/api/`. Этот код попадает в стартовый бандл.
4. **Хранилища Pinia раздела кладутся в папку раздела** (`src/desktop/trips/store.ts`). Если хранилище нужно нескольким
   частям, оно кладётся в `src/shared/`.

## PWA

- `src-pwa/manifest.json` задаёт `scope` и `start_url` равными `/m/`: на телефон устанавливается только мобильная часть.
- `src-pwa/register-sw.ts` регистрирует service worker со scope `/m/`: десктопная часть и администрирование работают без
  service worker.
- `quasar.config.ts` > `pwa` исключает чанки `desktop-*` и `admin-*` из кэша service worker и разрешает открытие без
  сети только для адресов `/m/...`.
- У `src-pwa/` собственный `package.json` (Workbox и `register-service-worker`). Его зависимости ставит `npm install` в
  корне через скрипт `postinstall`.

## Тексты и переводы

Ключ текста — сам русский текст: `t('Ввести вагон')`. Отдельные ключи вида `menu.trips` не придумываются.

- Русский текст показывается как есть. В `ru.json` только формы множественного числа:
  `"{n} вагонов": "{n} вагон | {n} вагона | {n} вагонов"`, вызов — `t('{n} вагонов', n)`.
- В `kk.json` и `en.json` переводы с русским текстом в качестве ключа: `"Вагоны": "Wagons"`. Нет перевода — показывается
  русский текст.
- Ключ ищется целиком, точка в тексте не делает ключ вложенным.
- Подстановки работают и без перевода: `t('с {date}', { date })`. Символы `{ } @ |` — синтаксис сообщений vue-i18n, в
  тексте они экранируются: `{'@'}`.
- `npm run i18n:check` находит тексты интерфейса без перевода в `kk.json` и `en.json` и переводы, текст которых
  исчез из исходников. Запускайте его после правки текстов.
- Если исправить русский текст, перевод на kk и en со старым ключом перестанет применяться — исправьте ключ и в
  `kk.json`, `en.json`.
- В компонентах и вне их используется `t` из `@/boot/i18n`. Тексты в данных (меню, колонки таблиц, значения фильтров)
  пишутся по-русски и переводятся при показе.

## Общие модули

| Модуль                               | Назначение                                                                                               |
| ------------------------------------ | -------------------------------------------------------------------------------------------------------- |
| `src/shared/bus.ts`                  | шина событий (mitt); все события и их данные описаны в `BusEvents`                                       |
| `src/shared/icons/`                  | иконки из макета (svg) и компонент `SvgIcon`                                                             |
| `src/shared/components/table/`       | таблица `DataTable`: колонки-описания, ячейка — компонент, подвал по колонкам и слот `footer`            |
| `src/shared/components/choice/`      | фильтры `CbButton`, `CbSegment`, `CbList`                                                                |
| `src/shared/components/dialog/`      | диалог `DialogFrame`, общий предок диалогов ввода `FormDialog` и `openDialog` — открытие диалога из кода |
| `src/shared/components/form/`        | поля форм: `TextInput` (текст), `FormField` (подпись над полем), `FormSection` (раздел формы)            |
| `src/shared/components/period/`      | выбор периода `PeriodPicker` и даты (с временем) `DatePicker` — все даты вводятся ими                    |
| `src/shared/dict/`                   | справочники: `DictManager`, реестр `dicts.ts`                                                            |
| `src/shared/ws.ts`                   | соединение с сервером по WebSocket (STOMP), каналы `/topic/<имя>`                                        |
| `src/shared/db/db.ts`                | локальная база IndexedDB (Dexie)                                                                         |
| `src/shared/user.ts`                 | текущий пользователь: роли, депо, текущий рейс; загружается один раз, без сети — из копии                |
| `src/shared/network.ts`              | есть ли связь (`isOnline`)                                                                               |
| `src/shared/offline/`                | мобильная часть без сети: копии последних данных (`cache.ts`) и очередь заявок, исправлений и примечаний (`outbox.ts`) |
| `src/shared/requests/`               | заявки на ремонт для обеих частей: права (`rights.ts`), показ, карточка, выбор вагона и неисправности    |
| `src/desktop/menu/`                  | левое меню десктопной части, пункты — в `menu.json`                                                      |
| `src/desktop/frame/DesktopFrame.vue` | фрейм страницы: слоты `header`, тело и `right` (правая панель)                                           |
| `src/desktop/frame/FramePanel.vue`   | оформление правой панели: заголовок, крестик, подсказка «Выберите … в списке», тело                      |

Размеры в стилях задаются только в `rem` и `em`, ширина и высота — не точнее десятых (`2.1rem`). Высота полей
и кнопок рядом с ними — переменная `--zs-control-height`: 2.3rem в формах и редакторах, 2.1rem в панели фильтров
(`FilterBar`). Цвета и шрифты макета — переменные `$zs-*` в
`src/css/quasar.variables.scss`.

## Проверка состава чанков

После `npm run build`:

- в `dist/pwa/assets/` есть файлы `pwa-*.js`, `desktop-*.js` и `admin-*.js`;
- в `dist/pwa/sw.js` нет упоминаний `desktop-` и `admin-`.

## Структура

```
src/
  pwa/          мобильная часть: pwa.ts (точка входа), PwaLayout.vue, страницы по разделам
  desktop/      десктопная часть: desktop.ts (точка входа), DesktopLayout.vue, страницы по разделам
  admin/        администрирование: admin.ts (точка входа), страницы по разделам
  layouts/      общие layout (AuthLayout.vue — вход в систему)
  shared/       общий код: components/, icons/, dict/, db/, bus.ts, ws.ts, device.ts
  api/          HTTP-клиент сервера zhsr-app и функции API (пока с фиктивными данными)
  router/       маршруты (routes.ts) и правило выбора части по устройству (index.ts)
  stores/       корневой экземпляр Pinia
  i18n/         тексты: ru.json, kk.json, en.json
  boot/         загрузочные файлы Quasar: i18n, ws (соединение с сервером и DictManager)
  css/          глобальные стили и переменные Quasar
src-pwa/        manifest и регистрация service worker
e2e/            e2e-тесты Playwright
```
