# Демо-данные

Загружает `./env-reset --demo` (`prepare/db-reset --demo`) после начальных данных `db-data/default`: файлы по порядку
имён, `<nn>-<таблица>.tsv` - в
таблицу, `*.sql` - выполняются. Здесь всё, что у каждого заказчика своё: сотрудники, депо, парки отстоя, неисправности,
вагоны, маршруты, рейсы, заявки, шаблоны чек-листов. На рабочей БД этих данных нет.

Фото демо-заявок, чек-листов и описей - в `img/` (источники и лицензии - `img/README.md`); `./env-reset --demo` кладёт
их в хранилище файлов (`prepare/files-demo`), ссылки на них - `22-repair_request_photo.tsv`,
`34-check_list_value_photo.tsv`, `37-equip_list_value_photo.tsv`.

Время записано на момент 2026-10-29 07:05; `99-shift-time.sql` сдвигает его к моменту загрузки, поэтому данные всегда
свежие: рейс 002 Алматы - Астана в пути, заявки поданы час назад.

## Источник

tsv здесь - источник данных: правятся вручную, без нужды не меняются. Первоначально собраны (2026-11-03) из заготовок
API фронта (`zhsr-web/src/api`, главный источник) и выгрузки демо-базы zholserik
(`../zholserik/db/zholserik-demo.sql`); сборщик удалён.

Шаблоны чек-листов (`23`-`28`) собраны (2026-11-10) из zholserik: "Топ нарушений" и "Проверка качества уборки" - из
`tools/checklists/generate.py` (классификатор заказчика); "Приёмка вагона", "Медосмотр", "Инструктаж" - по ТЗ zholserik
(Ф-ПРВ-03, Ф-ПЕР-03, Ф-ПЕР-06), границы показателей медосмотра - демонстрационные. Казахские и английские тексты -
черновые, как и в zholserik.

Описи экипировки (`29`-`31`) собраны (2026-11-10): шаблон "Экипировка (Приказ №545)" - из Приказа №545, Приложение 2,
таблица норм для поездов внутриреспубликанского сообщения (`doc-raw/v1500013714.22-09-2025.rus.docx`); колонки норм
СВ, Купейный/РИЦ, Плацкарт - нормативы типов вагона "СВ", "Купейный", "Плацкартный"; норма "1 на состав в штабном вагоне"
- норматив типа вагона "Штабной"; вариант исполнения (например, матрац с натуральным или синтетическим наполнителем) -
не отдельный пункт: берётся норма первого варианта. Шаблон "Опись имущества" - перечень из zholserik
(`backend/src/main/resources/db/reference/property_items.sql`), без нормативов. Казахские и английские наименования
позиций - черновые.

Шаблон "Подготовка рейса" (проверка рейса) составлен по ТЗ zholserik (процесс "Подготовка рейса") и разделу
"Стандарты" шаблона "Топ нарушений".

Проверки и описи (`32`-`37`): вагон 15021 - "Приёмка вагона" (мастер депо), "Топ нарушений" (инструктор),
"Проверка качества уборки" (приёмщик), "Экипировка (Приказ №545)" (мастер экипировки), "Опись имущества" (мастер депо); ещё пять описей вагонов 27140, 27109, 17431, 17043 (рейс 002), 16532 -
требуемое количество посчитано по нормативам типа вагона и модели вагона;
рейс 002 - "Медосмотр" (медик, проводник Абенова), "Инструктаж" (инструктор, проводник), "Подготовка рейса" (ЛНП).
По нарушениям созданы заявки KZR-26-00182 ... KZR-26-00186 (дописаны в `18`, `19`, `21`). В чек-листах примерно
четверть пунктов - нарушения, пятая часть - без ответа (обязательные пункты отвечены); в описях недостача - примерно у
четверти позиций с нормативом (у "Описи имущества" нормативов нет). Половина заявок (`18`) - из чек-листов и описей: для каждой такой заявки есть
проверка "Приёмка вагона" (примерно 4 из 5) или опись "Экипировка (Приказ №545)" того же вагона, сохранённая в момент
подачи заявки, с нарушением (недостачей), которое ссылается на заявку; остальные нарушения - без заявок. Описание есть примерно у каждого второго значения пункта; многострочное описание записано в tsv с `\n`, перевод строки ставит
`38-multiline-comments.sql`. Фото к пунктам - в чек-листах 1-3 и 7-9 и описях 1-4 и 7 (первые в списках: списки упорядочены по времени начала): у нарушений и у одного
пункта без нарушения; фото пункта с заявкой - и фото заявки (дописаны в `22`, тот же файл).
