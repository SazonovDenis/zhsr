# Станции, перегоны и линии перегонов из OpenStreetMap

Инструкция для Claude: как заново собрать `db-data/default/01-station.tsv`, `02-stage.tsv`, `03-stage_point.tsv`.
Первая сборка - 2026-11-02, данные OSM на 2026-11-01.

## Что получается

- `01-station.tsv` - станции: `id`, `code`, `name`, `stage_point`, `description` (не загружается).
  - `code`: код ЕСР (тег `esr:user`); если его нет - `OSM<id точки OSM>`. Код уникален (`uq_station_code`).
  - `name`: тег `name:ru`, иначе `name`; поправки - `NAME_FIX` и `NAME_PREFIX` в `build_graph.py`.
  - `stage_point`: точка станции - id первой точки первого её перегона, где она `from_station`, или последней, где
    она `to_station`; концы остальных её перегонов совпадают с этой точкой по координатам.
  - `description`: id точки OSM, склеенные дубли, `uic_ref`, пометка «вне Казахстана, транзит».
- `02-stage.tsv` - перегоны: ребро между соседними станциями, `from_station < to_station`, `km` - по линии пути.
- `03-stage_point.tsv` - линия перегона для карты: `id`, `stage`, `seq`, `x` (долгота), `y` (широта). Точки идут от
  `from_station` к `to_station`; первая точка - координаты `from_station`, последняя - `to_station`.

В `build/osm/out` файлы - без номера порядка загрузки: `station.tsv`, `stage.tsv`, `stage_point.tsv`.

id станций и перегонов при каждой сборке выдаются заново (станции - по алфавиту имени). БД пересоздаётся с нуля,
поэтому это допустимо, но всё, что ссылается на id станций в других tsv, надо перепривязать: демо-данные
`db-data/demo` (депо, парки отстоя, станции маршрутов, расположение вагонов).

## Шаги

Рабочий каталог по умолчанию - `build/osm` от корня проекта (в git не попадает). Выгрузка ~35 МБ.

1. `db-data/default/osm/fetch.sh` - скачать из Overpass API. Сервер часто занят (502, timeout): скрипт повторяет попытки и
   пропускает уже скачанные части; если какая-то часть «НЕ СКАЧАН» - просто запустить ещё раз. Долго: до часа.
   Запускать в фоне.
2. `db-data/default/osm/build.sh` - собрать в `build/osm/out` и сверить с текущими `db-data/default`. db-data не меняются.
3. Просмотреть вывод (см. «Что проверять»).
4. `db-data/default/osm/build.sh --apply` - скопировать tsv в `db-data/default`.
5. Перепривязать id станций в `db-data/demo`: по коду станции, затем по названию.

Python 3 без сторонних библиотек; curl.

## Что проверять в выводе build.sh

- `части сети [N]` - должна быть одна часть. Несколько частей - где-то разрыв: см. «Известные ловушки».
- Строки `цепочка ... км` - транзит через станции вне Казахстана. Ожидаемые (2026-11): Шөлдала - Куркуреусу
  (Турксиб через Кыргызстан), Магнай - Каерак (Троицк-ГРЭС), Джаныбек - Сайхин (Эльтон), Пахтаарал - Сарыагаш
  (Узбекистан), Елимай - Бускуль (Тамерлан), Аул - разъезд Казахстанский (Локоть), Жайсан - Чингирлау (Илецк),
  Мынколь - Куркамыс (Кулунда), Молодость - Акколь (Астрахань). Появилась цепочка через Курган, Омск, Орск,
  Саратов или Китай - это обход, а не внутренняя связь: уменьшить `TRANSIT_KM`.
- Сверка `check_km.py`: для каждого прежнего перегона - кратчайший путь в новом графе. `<<<` - расхождение больше 6%.
  Пара-тройка `<<<` даже при сверке с самим собой - нормально: кратчайший путь через соседние станции бывает чуть
  короче прямого перегона. Много `<<<` или `None` - разбираться.
- Первая сборка расходилась с прежним ручным `stage.tsv` (км по расписаниям поездов) на 0-2%; заметно - Караганды -
  Нурлы Жол (235 против 203) и Макат - Атырау (122 против 130).

## Как устроен build_graph.py

1. Станции: `railway=station`, кроме метро и LRT; остановочные пункты (`halt`) не берутся. Дубли - один код ЕСР или
   одно имя ближе `DUP_KM` - склеиваются в одну станцию.
2. Граф путей: `railway=rail` без `service=*` (подъездные, станционные пути и съезды не нужны).
3. Разрывы: тупиковый конец пути склеивается с ближайшим узлом другого пути ближе `GAP_KM` (в OSM это частая ошибка).
4. Узлы путей ближе `OWN_KM` принадлежат ближайшей станции.
5. Перегон: Дейкстра от узлов станции A до первого узла другой станции B; км - от точки станции A до точки B.
6. Транзит: станции вне Казахстана (не в `kz.json`) нужны только там, где через них проходит сеть Казахстана.
   Цепочка берётся, если она не длиннее `TRANSIT_KM` и без неё путь по сети длиннее в `TRANSIT_GAIN` раз или его нет.
7. Линия перегона упрощается Дугласом-Пекером с точностью `SIMPLIFY_KM` (50 м).

## Известные ловушки

- Выборка по полигону Казахстана (`area`) для путей не годится: Турксиб между Таразом и Шымкентом проходит через
  Кыргызстан, Уральск связан с сетью через Россию. Поэтому пути - по прямоугольнику, а полигон - только для списка
  станций Казахстана (`kz.json`).
- Overpass не отдаёт прямоугольник целиком (timeout) - поэтому шесть полос по долготе и склейка `merge_tiles.py`.
- `overpass.kumi.systems` может отдавать данные старее основного сервера.
- Часть магистралей в OSM без тега `usage` - поэтому фильтр «без `service`», а не «`usage=main|branch`».
- Устаревшие `name:ru` (у Шымкента было «Чимкент») - в `NAME_FIX`.
