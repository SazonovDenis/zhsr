# Демо-сервер zhsr

Разработчик запускает все команды на своей машине в каталоге `install` проекта. Скрипты сами выполняют нужные команды
на сервере по ssh.

## Первое развёртывание

1. Разработчик запускает в AWS instance EC2 (**Launch instance**): AMI Ubuntu 24.04, **Instance type**
   `t3.small`/`t4g.small` или больше, **Storage** не меньше 20 ГБ. В **Security group** instance разработчик
   открывает порты 22, 80 и 443. Key pair разработчик создаёт по инструкции [aws-key.md](aws-key.md).
2. Разработчик записывает в `.env` проекта пользователя и **Public IPv4 DNS** instance в `DEPLOY_HOST` и путь к
   private key в `DEPLOY_SSH_KEY` (образец - `.env.sample`).
3. Разработчик входит в Docker Hub под аккаунтом `sazonovden`: `docker login`.
4. Выполнить `./remote-setup` - устанавливает на сервер Docker, включает swap и создаёт на сервере `.env` со случайными
   паролями.
5. Выполнить `./build-app && ./build-app-docker-push`: собрает приложение локально и публиукет образы в Docker Hub.
6. Выполнить `./remote-reset --demo` - создаёт на сервере БД с демо-данными и запускает приложение.

Приложение открывается по адресу `https://<IP сервера>/`. Сервер пока работает с самоподписанным сертификатом, поэтому
браузер показывает предупреждение. Логины и пароли демо-пользователей перечислены в `db-data/demo/README.md`.

## Новая версия

Разработчик собирает и публикует образы, затем обновляет сервер:

```
./build-app && ./build-app-docker-push
./remote-update
```

Если в новой версии изменилась структура БД, разработчик запускает `./remote-reset --demo` вместо `./remote-update`.

### Частичное обновление

Скрипты `./build-app`, `./build-app-docker-push` и `./remote-update` принимают ключи `app` (сервер), `database`
(миграции БД) и `web` (фронт и nginx): тогда скрипты собирают, публикуют и обновляют на сервере только эти части. Без
ключей скрипты обрабатывают всё приложение.

| Что изменилось                                    | Команды                                                                                                  |
|---------------------------------------------------|----------------------------------------------------------------------------------------------------------|
| Сервер (`zhsr-app`)                               | `./build-app app && ./build-app-docker-push app`, затем `./remote-update app`                            |
| Фронт (`zhsr-web`)                                | `./build-app web && ./build-app-docker-push web`, затем `./remote-update web`                            |
| Конфигурация nginx                                | `./build-app web && ./build-app-docker-push web`, затем `./remote-update web`                            |
| Миграции БД без изменения прежних changeSet       | `./build-app database app && ./build-app-docker-push database app`, затем `./remote-update database app` |
| Данные `db-data` (справочники, демо-данные, фото) | `./remote-reset --demo`                                                                                  |
| Структура БД (прежние changeSet изменены)         | `./build-app && ./build-app-docker-push`, затем `./remote-reset --demo`                                  |
| Всё сразу или неясно что                          | `./build-app && ./build-app-docker-push`, затем `./remote-update`                                        |

## Пересоздание данных

`./remote-reset --demo` - пересоздаёт на сервере БД и хранилище файлов с демо-данными.

- `./remote-reset --<каталог>` загружает вместо демо-данных данные `db-data/<каталог>`, например `--kazrail`.
- `./remote-reset` загружает только `db-data/default`.
- Скрипт `./remote-reset` копирует данные на сервер по ssh: файлы `*.tsv` и `*.sql` и фото `img/*.jpg`. Docker-образы
  данных не содержат.
- `./remote-reset` с любым ключом стирает все прежние данные на сервере.

## HTTPS

Когда у сервера появится домен, разработчик запускает `./remote-ssl <домен> <почта>`. Скрипт получает сертификат
Let's Encrypt, ставит его вместо самоподписанного и настраивает на сервере его автоматическое продление.

## Работа на сервере

Разработчик входит на сервер командой `ssh -i <ключ> <DEPLOY_HOST>` и переходит в каталог `/opt/zhsr`. В каталоге
лежат скрипты:

- `./app-logs [сервис]` показывает журнал сервиса, по умолчанию - сервера `zhsr-app`;
- `./app-stop` останавливает приложение, `./app-start` запускает.
