## Журнал и состояние: План и Факт

### Цели

- Техника решает три задачи для объекта, атрибуты которого меняются во времени:
    - планирование изменений атрибутов;
    - отметка фактических изменений, в том числе исполнения запланированных;
    - получение атрибутов объекта по Плану и по Факту на любой момент времени.
- Решение задач на примере поезда — в п. 14.

### Термины

- Объект — сущность, атрибуты которой меняются во времени (например, вагон).
- Группа — объекты, атрибуты которых зависят друг от друга (например, вагоны одного поезда: отцепка одного вагона сдвигает позиции вагонов за ним).
- Журнал — таблица событий. Запись журнала — одно событие объекта в момент времени с атрибутами события (например, прицепка вагона: время, поезд, позиция, станция, рейс). Журналом служит и таблица документов, которые меняют атрибуты объекта (например, акт передачи вагона).
- Состояние — таблица атрибутов объекта с периодом действия. Запись состояния хранит атрибуты объекта и период, в котором атрибуты действуют (например, вагон в поезде на позиции 3 с 10:00 до 18:00).
- План — слой записей, которые описывают намеченное.
- Факт — слой записей, которые описывают произошедшее.
- Слой записи хранится в поле kind. Таблица журнала и таблица состояния содержат записи обоих слоёв.
- Связанная сущность — запись другой таблицы с плановым временем, к которому привязан План (например, рейс с плановым отправлением).

### 1. Журнал

- Запись журнала хранит объект, вид события, время события и атрибуты события.
- Порядок событий объекта задают правила предметной области (например, прицепка и отцепка вагона идут по очереди). Правила порядка действуют внутри каждого слоя отдельно.

### 2. Состояние

- Период записи состояния: начало (dbeg) входит в период, конец (dend) не входит.
- Запись с пустым концом называется открытой: атрибуты действуют до сих пор. Запись с заполненным концом называется закрытой.
- Смена атрибутов выполняется двумя действиями: открытая запись изменяется — в поле dend заносится время смены (запись закрывается); создаётся новая запись с началом, равным времени смены. Закрытые записи изменяются только при удалении ошибочного Факта (п. 7) и при отмене отметки (п. 9).
- Запись состояния может хранить несколько атрибутов (например, поезд и позиция) и атрибут-набор (например, несколько ответственных сотрудников). Набор хранится в подчинённой таблице: одна строка — один элемент набора, строка ссылается на запись состояния. Изменение любого атрибута, в том числе состава набора, — смена атрибутов.
- Периоды записей одного объекта не пересекаются внутри слоя. Правило проверяет БД ограничением исключения по tstzrange(dbeg, dend).
- Атрибуты объекта на момент t находит условие dbeg <= t and (dend is null or t < dend). Если записи на момент t нет, у объекта на этот момент атрибутов нет (например, вагон не в поезде).
- Разные состояния одного объекта (например, расположение, ответственные, участие в поезде) хранятся в отдельных таблицах. Атрибуты объекта на момент t собираются из всех состояний на момент t.

### 3. Слои План и Факт

- Слой Факт состояния хранит историю: атрибуты, которые действовали на деле.
- Слой План состояния хранит ожидаемое состояние: Факт на время последнего Факта группы, изменённый ожидающими записями Плана журнала (п. 5). Историю Плана слой План не хранит.
- Запись Факта журнала создаётся со временем не позже текущего. Запись Плана журнала создаётся со временем в будущем.
- Построение состояния не сверяет записи Плана журнала с записями Факта журнала: время и атрибуты Факта могут отличаться от Плана. Записи Плана и Факта журнала сопоставляет только отметка исполнения (п. 6, п. 9). Проверки между слоями (например, вагон по Факту в одном поезде, а по Плану — в другом в то же время) выполняет приложение по правилам предметной области.

### 4. Способы изменения состояния

- Слой Факт состояния изменяется тремя способами:
    - записью Факта журнала без Плана (например, внеплановая прицепка);
    - отметкой исполнения Плана (п. 6, п. 9);
    - напрямую, без журнала: запись состояния появляется без события.
- Слой План состояния изменяется двумя способами:
    - перестроением по журналу (п. 5);
    - напрямую, без журнала (п. 9).
- Способы сочетаются без ограничений. Схема допускает:
    - Факт без Плана;
    - План без Факта (статусы Плана — п. 8);
    - План, отработанный с отклонением по времени или атрибутам;
    - План, который меняет атрибуты, полученные без Плана (например, плановая отцепка вагона, прицепленного без плана).
- Вырожденный случай: состояние без журналов и без Плана — обычная таблица версионных значений.

### 5. Применение записи журнала к состоянию

- Запись журнала одного слоя изменяет записи состояния того же слоя у всех объектов группы, атрибуты которых событие изменило:
    - открытая запись состояния объекта закрывается временем события;
    - создаётся новая запись состояния объекта с началом, равным времени события, если после события у объекта есть атрибуты. Атрибуты после события — атрибуты закрытой записи, изменённые событием (например, отцепка вагона уменьшает на 1 позиции вагонов за ним; у отцепленного вагона атрибутов нет, новая запись не создаётся).
- Записи журнала с одинаковым временем применяются вместе: у каждого объекта, атрибуты которого изменились, закрывается одна запись и создаётся одна запись.
- Слой Факт: запись Факта журнала применяется к состоянию при создании. Время новой записи Факта не раньше времени последней записи Факта группы и последней записи Факта объекта.
- Слой План перестраивается при каждом изменении журнала группы, в Плане или в Факте:
    - записи Плана состояния группы удаляются;
    - записи Факта состояния группы, открытые на время последней записи Факта группы, копируются в слой План с тем же началом;
    - записи Плана журнала группы со статусом «ожидает» применяются по порядку времени; время применения — время записи Плана, но не раньше времени последней записи Факта группы.
- Записи Плана журнала со статусами «отработан» и «отменён» в перестроении не участвуют.
- Изменение журнала и изменение состояния выполняются в одной транзакции.

### 6. Отметка исполнения Плана журнала

- Отметка исполнения — действие пользователя, которое подтверждает, что запланированное событие произошло. Отметка выполняет в одной транзакции три изменения:
    - создаётся запись Факта журнала со ссылкой на запись Плана; время и атрибуты записи Факта берутся из записи Плана, пользователь может их исправить; запись Факта применяется к слою Факт состояния (п. 5);
    - статус записи Плана изменяется на «отработан»; время и атрибуты записи Плана не изменяются;
    - слой План состояния группы перестраивается (п. 5).
- Ссылка записи Факта на запись Плана необязательна: пустая ссылка означает событие без Плана.
- Запись Плана и запись Факта хранят свои время и атрибуты, поэтому приложение показывает отклонение Факта от Плана: опоздание, другую станцию, другой рейс.
- Отмена отметки — удаление записи Факта (п. 7).

### 7. Удаление ошибочной записи Факта журнала

- Удалить можно только запись Факта со временем последней записи Факта группы, и только если у объекта нет более поздних записей Факта в других группах.
- Записи состояния, которые событие создало и закрыло, приложение находит по группе и времени события. Удаление выполняет в одной транзакции пять изменений:
    - удаляются записи Факта состояния группы с началом, равным времени события;
    - у записей Факта состояния группы с концом, равным времени события, очищается конец;
    - запись Факта журнала удаляется, остальные записи Факта журнала группы с тем же временем применяются заново (п. 5);
    - если запись Факта ссылается на запись Плана, статус записи Плана изменяется на «ожидает»;
    - слой План состояния группы перестраивается (п. 5).

### 8. Статусы записи Плана

- Запись Плана хранит статус (plan_status): «ожидает», «отработан» или «отменён». Статус хранит запись Плана журнала, а если План меняют напрямую в состоянии, — запись Плана состояния. Запись Факта статуса не имеет.
- Запись Плана создаётся со статусом «ожидает».
- Изменяется только запись Плана со статусом «ожидает». Запись Плана со статусом «отработан» не изменяется.
- Отмена Плана изменяет статус записи Плана на «отменён»; запись не удаляется. Запись Плана со статусом «отменён» не участвует в правилах порядка событий и в построении состояния.
- Просроченный План — запись Плана со статусом «ожидает», время которой уже прошло. Пользователь отмечает исполнение просроченного Плана, отменяет его или переносит время в будущее. Приложение показывает просроченный План отдельно от Плана с временем в будущем.
- История изменений Плана в задачу не входит. Если история понадобится, изменение записи Плана выполняется так: запись Плана получает статус «отменён», создаётся новая запись Плана. Записи Плана со статусом «отменён» хранят историю.

### 9. План напрямую в состоянии (без журнала)

- Записи Плана состояния создаются и изменяются напрямую (например, план ответственных за вагон на рейс).
- Создание записи Плана в середине цепочки изменяет запись Плана, которая действует на начало новой записи: конец действующей записи становится равен началу новой записи. Новая запись получает конец, равный началу следующей записи Плана; если следующей записи нет, конец пустой.
- Отмена записи Плана изменяет конец предыдущей записи Плана: конец становится равен началу следующей неотменённой записи Плана, а если следующей нет — очищается.
- Отметка исполнения выполняет в одной транзакции два изменения:
    - в слое Факт состояния открытая запись закрывается временем отметки и создаётся новая запись Факта с атрибутами из записи Плана; пользователь может исправить атрибуты; если атрибуты совпадают с атрибутами открытой записи Факта, слой Факт не изменяется;
    - статус записи Плана изменяется на «отработан».
- Запись Факта состояния не ссылается на запись Плана. Отмена отметки находит записи по времени отметки: удаляется запись Факта с началом, равным времени отметки; у записи Факта с концом, равным времени отметки, очищается конец; статус записи Плана изменяется на «ожидает».

### 10. Привязка Плана к связанной сущности по времени

- Запись Плана может не ссылаться на связанную сущность. Тогда приложение находит запись Плана по объекту и времени: время записи Плана равно плановому времени связанной сущности.
- Достоинство: журнал и состояние не зависят от таблицы связанной сущности.
- Недостаток: перенос планового времени связанной сущности требует переноса записи Плана. Приложение отменяет прежнюю запись Плана и создаёт новую с новым временем.

### 11. Выбор слоя по состоянию связанной сущности

- Чтобы получить атрибуты объекта в рамках связанной сущности, приложение выбирает слой по состоянию связанной сущности:
    - связанная сущность ещё не началась → слой План на плановое время связанной сущности: ожидаемое состояние;
    - связанная сущность идёт → открытая запись Факта;
    - связанная сущность завершилась → запись Факта, которая действовала в момент завершения.
- Одно условие SQL выражает все три случая, поэтому списки и проверки прав используют один запрос.

### 12. Текущие атрибуты в карточке объекта

- Карточка объекта — таблица с одной строкой на объект. Строка карточки хранит ссылку на открытую запись Факта состояния или копию текущих атрибутов. Приложение читает текущие атрибуты из карточки, без поиска в состоянии.
- Каждое изменение слоя Факт состояния обновляет карточку объекта в той же транзакции.

### 13. Чтение

- Атрибуты объекта на момент t по Факту — условие п. 2 по записям слоя Факт. Ожидаемые атрибуты объекта на момент t после последнего Факта группы — то же условие по записям слоя План. Объекты с заданным атрибутом на момент t — то же условие с отбором по атрибуту.
- Запланированные события — записи Плана журнала со статусом «ожидает». Произошедшие события — записи Факта журнала.
- История группы на экране: слева записи Факта журнала по времени, после последнего Факта — ожидающие записи Плана журнала; справа — состояние на время выбранной записи: для записи Факта — слой Факт, для записи Плана — слой План.

### 14. Пример: состав поезда

- Группа — вагоны одного поезда. Журнал прицепок и отцепок (train_wagon_change): запись — прицепка или отцепка вагона, слой План или Факт. Прицепка задаёт позицию: вагоны с этой позиции и дальше сдвигаются на 1 назад; позиция больше числа вагонов ставит вагон последним. Отцепка сдвигает вагоны за отцепленным на 1 вперёд. Перестановка вагона — отцепка и прицепка на новую позицию.
- Состояние участия вагона в поезде (train_wagon): атрибуты — поезд и позиция.
- Планирование прицепок и отцепок — создание, изменение и отмена записей Плана журнала.
- Отметка фактической прицепки и отцепки — отметка исполнения Плана или создание записи Факта без Плана.
- Фактический состав поезда на момент t — записи слоя Факт с этим поездом на момент t, по позиции. Ожидаемый состав — то же по слою План; его читают рейс до отправления, план ответственных на рейс, норма проводников.
- Ограничение исключения в слое Факт не допускает вагон в двух поездах одновременно. В слое План занятость вагона проверяет приложение при планировании: просроченный План применяется временем последнего Факта своего поезда, поэтому ожидаемые составы двух поездов могут на время пересечься.

| 1  | В1    | План | отработан   | прицепка | 10:00 | П1    | 1   |      |
| 2  | В1    | План | ожидает     | отцепка  | 18:00 | П1    |     |      |

- Запись 4 — прицепка В2 без Плана на позицию 1: В1 сдвинулся на позицию 2.
- Запись 5 — плановая отцепка В2, прицепленного без Плана. Запись 6 — плановая прицепка В3 на позицию 2.
