# zhsr: техническое задание - сущности

## 1. Места и парк

### Станция

- **Таблицы:** `station`.
- **Атрибуты:** код (уникален), название ([station.tsv](../db-data/station.tsv)).

#### Перегон

- **Таблицы:** `stage`.
- **Назначение:** граф железных дорог: станции - вершины, перегоны - рёбра.
- **Атрибуты:** две станции, расстояние в км ([stage.tsv](../db-data/stage.tsv)).
- **Правила:** направление не важно; пара станций - один перегон.

### Депо

- **Таблицы:** `depot`.
- **Атрибуты:** код (уникален), название, станция.

### Парк отстоя

- **Таблицы:** `yard`.
- **Назначение:** место расположения вагонов при станции, как депо.
- **Атрибуты:** код (уникален), название, станция.

### Вагон

- **Таблицы:** `wagon`.
- **Назначение:** справочник.
- **Атрибуты:** номер (уникален), тип вагона ([wagon_type.tsv](../db-data/default/04-wagon_type.tsv)), модель
  ([model_type.tsv](../db-data/default/05-model_type.tsv)), год постройки, даты ввода в эксплуатацию и вывода из эксплуатации, депо
  приписки (`depot`), прочие паспортные данные (`data`).
- **Правила:**
    - вагон в эксплуатации, пока дата вывода из эксплуатации не указана; дата вывода - не больше текущей;
    - с датой вывода вагон переходит в состояние "отставлен" (парк "исключён").

#### Журналы вагона

- **Таблицы:** `wagon_location`, `wagon_status`, `wagon_responsible`.
- **Атрибуты:**
    - расположение: ровно одно из - станция, депо, парк отстоя, рейс ([location_type.tsv](../zhsr-database/src/main/resources/db/dict/location_type.tsv));
    - состояние: [wagon_status_type.tsv](../zhsr-database/src/main/resources/db/dict/wagon_status_type.tsv);
    - ответственные за вагон: несколько сотрудников (`wagon_responsible_usr`); отсутствие открытой записи факта -
      ответственных нет.
- **Правила:**
    - запись действует с `dbeg` по `dend` (не включая); `dend` пуст - текущая запись. Периоды вагона не
      пересекаются;
    - изменение - закрыть текущую запись и открыть новую в одной транзакции;
    - документы ссылаются на записи, которые открыли; запись без ссылки - ввод вагона, ручная правка или отметка
      отправления или прибытия рейса;
    - записи, которые открыла отметка отправления (прибытия) рейса, - текущие записи вагонов поезда рейса с `dbeg`,
      равным времени отправления (прибытия);
    - отмена акта, прицепки или отцепки удаляет записи, которые открыл документ, и снова делает текущими предыдущие.
- **Ответственные - план и факт:**
    - журнал ответственных хранит два слоя: план и факт; периоды факта вагона не пересекаются, план и факт между собой
      не сверяются; `dend` пуст - период факта открыт;
    - статус плана: ожидает, отработан, отменён; отметка факта по плану переводит план в "отработан", совпали даты или
      нет;
    - снятие всех ответственных закрывает запись факта и новой не открывает; документ хранит и открытую, и закрытую
      запись факта: отмена документа удаляет открытую и снова открывает закрытую;
    - план - про будущее: план правится, пока его не отработали и не отменили; факт - про свершившееся: время факта
      не позже текущего; факт ответственных вагонов рейса меняют в любом статусе рейса, кроме "отменён", в том числе
      до отправления (Ф-РЕЙ-08);
    - план ответственных бывает только у рейса: запись плана ссылается на рейс и его стадию (`trip`, `trip_point`);
      у рейса два плана, оба заданы у вагонов его поезда: план ответственных на рейс - стадия "отправление" (с
      планового отправления), план ответственных после рейса - стадия "прибытие" (с планового прибытия: плановое
      отправление плюс время в пути маршрута); план на произвольную дату не задаётся; у вагона один ожидающий план на
      стадию рейса; начало плана - справочно: Система находит план по рейсу и стадии, а не по дате;
    - план на рейс строит распределение по вагонам (Ф-РЕЙ-06, Ф-РЕЙ-08): ответственные - только из бригады рейса;
      план после рейса пользователь задаёт сам (Ф-РЕЙ-08): Система предлагает бригаду рейса и сотрудников депо
      станции прибытия; план после рейса без ответственных не хранится - после прибытия остаются ответственные рейса;
    - отметка отправления отрабатывает план на рейс: факт временем отправления с рейсом и стадией "отправление",
      план - "отработан"; вагон без плана на рейс остаётся в пути без ответственных; отметка прибытия так же
      отрабатывает план после рейса, вагон без плана после рейса не меняется; отмена отметки находит эти факты по
      рейсу и стадии, удаляет их и возвращает план в "ожидает", исправление времени отметки переносит их время;
    - факт, внесённый в рейсе без отметки (Ф-РЕЙ-06, Ф-РЕЙ-08), ссылается на рейс без стадии;
    - при правке рейса справочное начало планов рейса переносится на новые плановые отправление и прибытие; при смене
      поезда, отмене и удалении рейса планы отменяются; уход сотрудника из бригады убирает его из планов рейса.

#### Текущее состояние вагона

- **Таблицы:** `wagon_info`.
- **Назначение:** быстрое построение списков вагонов (Ф-ВАГ-04).
- **Атрибуты:** вагон (одна запись на вагон), текущее расположение и его начало, текущее состояние и его начало,
  текущие ответственные (ссылка на открытую запись факта журнала ответственных), общий пробег.
- **Правила:** все поля - копия текущих записей журналов вагона; обновляется в одной транзакции с журналами. Общий
  пробег - пробег на момент ввода вагона плюс участки пробега вагона (`wagon_run`); Система пересчитывает общий
  пробег после прибытия рейса, отцепки в рейсе и их отмены.

## 2. Маршрут, поезд и рейс

### Маршрут

- **Таблицы:** `route`.
- **Атрибуты:** номер поезда (уникален), название, нормы часов бригады
  (целые часы), даты начала и окончания действия, признак "разовый", пассажирский или грузовой
  ([transport_type.tsv](../zhsr-database/src/main/resources/db/dict/transport_type.tsv)).
- **Правила:** маршрут действует, пока период действия открыт: дата окончания не указана; дата окончания - не больше
  текущей. Время в пути маршрута система считает по остановкам: прибытие на конечную станцию минус отправление с
  начальной.

#### Остановка маршрута

- **Таблицы:** `route_station`.
- **Атрибуты:** маршрут, порядок (уникален в маршруте), станция, километраж, время прибытия и время отправления
  (минуты от полуночи дня отправления с начальной станции; у начальной станции нет прибытия, у конечной - отправления).

### Поезд

- **Таблицы:** `train`.
- **Назначение:** вагоны, сцепленные вместе. Поезд ходит из рейса в рейс по разным маршрутам, состав поезда почти не
  меняется.
- **Атрибуты:** обозначение (уникально среди действующих поездов), когда сформирован, когда расформирован.
- **Правила:**
    - поезд создаёт планировщик вагонов; обозначение поезда вводит планировщик вагонов;
    - поезд действует, пока дата расформирования не указана;
    - Система расформировывает поезд, когда отцеплен последний вагон поезда и у поезда нет ожидающих плановых
      прицепок;
    - поезд в каждый момент идёт не больше чем в одном рейсе.

#### Прицепка и отцепка

- **Таблицы:** `train_wagon_change` - журнал прицепок и отцепок поезда по технике «журнал и состояние»
  ([journal-state-plan-fact.md](db-doc/journal-state-plan-fact.md)).
- **Атрибуты:**
    - поезд, вагон, вид (прицепка, отцепка), слой (план, факт), статус плана (ожидает, отработан, отменён);
    - время: у плана плановое, у факта фактическое; станция; позиция прицепки;
    - рейс и остановка маршрута рейса - у прицепки и отцепки в рейсе;
    - у факта - отработанный им план;
    - кто внёс, основания и примечания (приказ, причина);
    - записи журналов вагона, открытые фактом в рейсе.
- **Правила:**
    - пользователь оформляет прицепку и отцепку фактом или планом; план создаётся со статусом "ожидает" и временем в
      будущем;
    - прицепка ставит вагон на позицию: вагоны с этой позиции и дальше сдвигаются на одну назад; позиция больше
      числа вагонов ставит вагон последним; отцепка сдвигает вагоны за отцепленным на одну вперёд; перестановка вагона
      - отцепка и прицепка на новую позицию;
    - отметка исполнения плана создаёт факт со ссылкой на план и переводит план в "отработан"; время, станция и
      позиция факта могут отличаться от плана, отклонение видно в журнале;
    - отмена плана переводит план в "отменён"; отработанный и отменённый план не меняется;
    - факт вносится временем не раньше последнего факта поезда и последнего факта вагона;
    - ошибочный факт удаляется без истории, и только факт со временем последнего факта поезда: Система удаляет факт
      и записи журналов вагона, которые он открыл, строит участие вагонов поезда с этого времени заново, отработанный
      фактом план снова "ожидает";
    - просроченный план - ожидающий план, время которого прошло; пользователь отмечает его исполнение или отменяет;
    - прицепка и отцепка на станции вне рейса журналы вагона не меняют;
    - факт прицепки и отцепки в рейсе задаёт рейс и остановку маршрута и открывает записи журналов вагона; станция
      прицепки или отцепки в рейсе - станция остановки маршрута.

#### Участие вагона в поезде

- **Таблицы:** `train_wagon` - состояние по технике «журнал и состояние».
- **Атрибуты:** поезд, вагон, слой (план, факт), позиция в поезде, начало и конец периода.
- **Правила:**
    - участие строит Система по журналу прицепок и отцепок; пользователь участие напрямую не меняет;
    - слой "факт" - история составов поезда: каждый факт закрывает записи вагонов, позиция которых изменилась, и
      создаёт новые;
    - слой "план" - ожидаемый состав: вагоны поезда по факту на время последнего факта и ожидающие планы после него
      по порядку времени; просроченный план действует со времени последнего факта поезда; Система перестраивает слой
      "план" при каждом изменении журнала поезда;
    - состав поезда на момент - записи слоя на этот момент; ожидаемый состав читают рейс до отправления, план
      ответственных на рейс и норма проводников;
    - вагон в каждый момент входит не больше чем в один поезд по факту; позицию поезда в каждый момент занимает один
      вагон;
    - вагон занят в другом поезде с момента, если он есть в ожидаемом составе другого поезда после этого момента:
      плановая прицепка резервирует вагон.

### Рейс

- **Таблицы:** `trip`.
- **Атрибуты:**
    - маршрут, поезд, плановое отправление;
    - статус ([trip_status_type.tsv](../zhsr-database/src/main/resources/db/dict/trip_status_type.tsv));
    - отправление и прибытие: когда, кто, когда внесена отметка;
    - начальник поезда и ПЭМ - из бригады рейса (`trip_crew`).
- **Правила:**
    - рейс - поездка поезда по маршруту;
    - станция отправления рейса - первая остановка маршрута, станция прибытия - последняя;
    - отправление раньше прибытия;
    - вагоны рейса - вагоны поезда рейса на время рейса: до отправления - ожидаемый состав на отправление, в пути и
      после - по факту.

#### Пробег вагона за рейс

- **Таблицы:** `wagon_run`.
- **Атрибуты:** вагон, рейс, участие вагона в поезде (факт прицепки, с которого участие началось), пробег в км.
- **Правила:**
    - участок пробега - путь вагона в поезде рейса от начальной станции маршрута или остановки прицепки до конечной
      станции маршрута или остановки отцепки; пробег - разность километража этих остановок;
    - Система вносит участок пробега при прибытии рейса и при отцепке в рейсе и удаляет участок пробега при отмене
      прибытия или отцепки;
    - вагон, отцепленный и снова прицепленный в одном рейсе, имеет в рейсе два участка пробега.

#### Бригада рейса

- **Таблицы:** `trip_crew`.
- **Атрибуты:** рейс, сотрудник (`usr`), должность на рейсе ([crew_duty_type.tsv](../zhsr-database/src/main/resources/db/dict/crew_duty_type.tsv)): проводник,
  начальник поезда, поездной электромеханик (ПЭМ); заступление на дежурство и окончание дежурства.
- **Правила:**
    - бригада - роль на рейсе: строка бригады - дежурство сотрудника, один сотрудник - одна строка рейса;
    - за какие вагоны отвечает сотрудник, бригада не хранит: это журнал ответственных (план ответственных на рейс до
      отправления, факт в пути); проводник без вагона - проводник рейса, которого нет среди ответственных на рейс;
    - начальник поезда и ПЭМ - не больше одного на дежурстве в рейсе;
    - до отправления строки бригады правятся и удаляются; с отправления строки бригады не удаляются;
    - заступление на дежурство - отправление рейса; окончание дежурства - прибытие рейса.

## 3. Акты

Таблицы бумажных документов - с суффиксом `_act`.

### Акт приёма-передачи

- **Таблицы:** `transfer_act`.
- **Атрибуты:**
    - номер (уникален), откуда: станция, депо или парк отстоя; куда: станция, депо или парк отстоя; вид работ
      ([work_type.tsv](../zhsr-database/src/main/resources/db/dict/work_type.tsv));
    - статус ([act_status_type.tsv](../zhsr-database/src/main/resources/db/dict/act_status_type.tsv)): ожидает приёма, проведён (принят), отказ, отменён; у
      отменённого - акт отмены;
    - кто и когда сдал; кто и когда принял или отказал; причина отказа в приёме;
    - вагоны - `transfer_act_wagon`: вагон (уникален в акте), порядок, с имуществом, комментарий, открытая приёмом
      запись расположения, открытая и закрытая передачей записи ответственных.
- **Правила:**
    - у "откуда" заполнено ровно одно из полей: станция, депо, парк отстоя; у "куда" - тоже ровно одно;
    - "откуда" и "куда" - разные расположения одной станции; станция на обеих сторонах не допускается;
    - станция акта - станция "откуда": сама станция или станция депо или парка отстоя;
    - "ожидает приёма" - необязательное состояние акта: приём не отмечен, расположение вагонов не меняется; акт можно
      оформить сразу принятым;
    - расположение вагонов меняется только при статусе "проведён" (принят);
    - отказ указывается с причиной;
    - отменяется весь акт целиком; после отмены поля приёма и отказа остаются такими, какими были до отмены.

### Акт отмены

- **Таблицы:** `act_cancellation`.
- **Назначение:** отмена акта приёма-передачи (Ф-АКТ-06).
- **Атрибуты:** кто и когда отменил, причина отмены.
- **Правила:**
    - отменённый акт получает статус "отменён" ([act_status_type.tsv](../zhsr-database/src/main/resources/db/dict/act_status_type.tsv)) и ссылку на акт
      отмены; статус "отменён" - только со ссылкой на акт отмены;
    - на один акт отмены ссылается один акт.

## 4. Заявки на ремонт

### Тип неисправности

- **Таблицы:** `fault_type`.
- **Назначение:** справочник неисправностей.
- **Атрибуты:** код (уникален), название, группа,
  критичность по умолчанию ([severity_type.tsv](../zhsr-database/src/main/resources/db/dict/severity_type.tsv)), служба-исполнитель
  ([service.tsv](../zhsr-database/src/main/resources/db/dict/service.tsv)), действует.
- **Правила:**
    - служба-исполнитель обязательна; группа и служба-исполнитель не связаны между собой;
    - тип неисправности, по которому есть заявки, не удаляется, а отключается; тип без заявок можно удалить.

#### Избранная неисправность

- **Таблицы:** `fault_type_favorite`.
- **Назначение:** частые неисправности: при подаче заявки Система показывает избранные неисправности первыми.
- **Атрибуты:** неисправность (один раз), порядок показа.
- **Правила:** администратор отмечает неисправность галочкой "В избранном" в карточке неисправности; новая избранная
  неисправность становится последней по порядку показа; запись удаляется вместе с неисправностью.

### Заявка на ремонт

- **Таблицы:** `repair_request`.
- **Атрибуты:** номер (уникален: код компании, год, порядковый номер в году), вагон, рейс,
  неисправность (`fault_type`), критичность, автор, время создания, время поступления, описание.
- **Правила:**
    - заявку подаёт пользователь (Ф-ЗАЯ-01) или создаёт Система (Ф-ЗАЯ-10);
    - автор корректирует заявку в течение 10 минут после подачи, пока не сменились
      исполнитель и статус; корректировка в журналы не попадает;
    - автор отменяет свою заявку (Ф-ЗАЯ-07).

#### Журнал статусов заявки

- **Таблицы:** `repair_request_status`.
- **Атрибуты:** заявка, статус ([request_status_type.tsv](../zhsr-database/src/main/resources/db/dict/request_status_type.tsv)),
  кто внёс запись, период действия записи.
- **Правила:**
    - запись действует с `dbeg` по `dend` (не включая); `dend` пуст - текущая запись. Периоды заявки не пересекаются;
    - первая запись вносится при подаче заявки, новая запись - при смене статуса и при передаче в депо новой заявки;
    - "кто внёс запись" - тот, кто подал заявку или сменил статус; пусто - запись внесла Система;
    - причина отказа или откладывания пишется примечанием к заявке (`repair_request_note`).

#### Движение заявки по исполнителям

- **Таблицы:** `repair_request_executor`.
- **Атрибуты:** заявка, исполнитель, кто внёс запись, период действия записи.
- **Правила:**
    - запись действует с `dbeg` по `dend` (не включая); `dend` пуст - текущая запись. Периоды заявки не пересекаются;
    - новая запись вносится при назначении, смене и снятии исполнителя; пока исполнителя не назначали, записей нет;
    - исполнитель пуст, если исполнитель снят;
    - "кто внёс запись" - тот, кто назначил или снял исполнителя; пусто - запись внесла Система.

#### Текущее состояние заявки

- **Таблицы:** `repair_request_info`.
- **Атрибуты:** заявка (одна запись на заявку), текущий статус и его начало, текущий исполнитель и его
  начало, служба-исполнитель.
- **Правила:**
    - статус и исполнитель - копия текущих записей журнала статусов и движения по исполнителям; обновляются в одной
      транзакции с журналами;
    - служба-исполнитель определяется типом неисправности заявки;
      запоминается при подаче заявки и при смене типа неисправности корректировкой; смена службы в справочнике поданные заявки
      не меняет.

#### Примечания и фото к заявке

- **Таблицы:** `repair_request_note`, `repair_request_photo`.
- **Атрибуты:**
    - примечание: заявка, автор, дата, время поступления, текст;
    - фото: заявка, автор, когда приложено, когда загружено, ключ файла в хранилище, размер.
- **Правила:** файл фото лежит в хранилище, в таблице - ссылка на него.

## 5. Чек-листы

### Шаблон ответов

- **Таблицы:** `check_dict`, `check_dict_value`.
- **Назначение:** готовый набор вариантов ответа для пунктов чек-листа: "Да / Нет", "В порядке / Нарушение".
- **Атрибуты:** шаблон ответов - название на трёх языках, порядок, отключён; вариант ответа - шаблон ответов, название
  на трёх языках, порядок, отключён.

### Шаблон чек-листа

- **Таблицы:** `check_list_template`, `check_list_template_item`.
- **Атрибуты:**
    - шаблон: название на трёх языках, объект проверки (вагон, сотрудник, рейс), порядок, отключён;
    - пункт: шаблон, раздел (пункт-родитель), текст на трёх языках, вид значения (строка, число, вариант ответа;
      пусто - раздел), шаблон ответов, порядок, отключён.

#### Норматив пункта чек-листа

- **Таблицы:** `check_list_item_norm`, `check_list_item_norm_value`.
- **Атрибуты:** пункт, тип вагона (пусто - для всех типов вагона), обязателен, границы числа, допустимые варианты
  ответа, критичный, неисправность заявки, период действия.
- **Правила:** нормативы пункта для одного типа вагона по периодам не пересекаются; текущий норматив - незакрытый
  (`dend` пуст).

### Чек-лист

- **Таблицы:** `check_list`, `check_list_value`, `check_list_value_photo`.
- **Атрибуты:**
    - чек-лист: шаблон, вагон, рейс, проверяемый сотрудник, кто проводил проверку, время начала, время завершения;
    - значение: чек-лист, пункт, строка, число, вариант ответа, описание нарушения, норматив, нарушение, заявка;
    - фото: значение, ключ файла в хранилище, размер, автор, когда приложено, когда загружено.
- **Правила:**
    - чек-лист приходит на сервер только завершённым;
    - пункт в чек-листе - один раз; заполняется не больше одного значения;
    - заявка по нарушению ссылается на тот же файл фото (`repair_request_photo.storage_key`).

## 6. Экипировка

### Шаблон описи экипировки

- **Таблицы:** `equip_list_template`, `equip_list_template_item`.
- **Атрибуты:**
    - шаблон: название на трёх языках, неисправность заявки по недостаче, порядок, отключён;
    - пункт: шаблон, раздел (пункт-родитель), текст на трёх языках, единица измерения (пусто - раздел), порядок,
      отключён.

#### Норматив позиции описи

- **Таблицы:** `equip_list_item_norm`.
- **Атрибуты:** пункт, тип вагона (пусто - для всех типов вагона), количество на единицу базы, база расчёта, способ
  сравнения, добавка для головного и хвостового вагона, норма текстом, критичный, период действия.

### Опись экипировки

- **Таблицы:** `equip_list`, `equip_list_value`, `equip_list_value_photo`.
- **Атрибуты:**
    - опись: шаблон, вагон, рейс, автор, время начала, время последнего сохранения, заявка по недостаче;
    - значение: опись, пункт, фактическое количество, требуемое количество, норматив, нарушение, примечание;
    - фото: значение, ключ файла в хранилище, размер, автор, когда приложено, когда загружено.
- **Правила:** опись приходит на сервер только завершённой; пункт в описи - один раз; заявка по недостаче ссылается
  на тот же файл фото (`repair_request_photo.storage_key`).

### Модель вагона

- **Таблицы:** `model_type`.
- **Атрибуты:** название, код, число мест, число купе, число окон.
- **Правила:** число мест, купе и окон - базы расчёта норм экипировки.

## 7. Сотрудники

### Сотрудник

- **Таблицы:** `usr`.
- **Назначение:** пользователь Системы; документы и журналы ссылаются на сотрудника, а не хранят ФИО текстом.
- **Атрибуты:** логин (уникален, как правило ИИН), ФИО, хэш пароля, телефон, учётная запись включена, когда заведён.
- **Правила:** отключение учётной записи не удаляет историю.

#### Роли сотрудника

- **Таблицы:** `usr_role`.
- **Атрибуты:** сотрудник, роль ([role_type.tsv](../zhsr-database/src/main/resources/db/dict/role_type.tsv)).
- **Правила:**
    - роль указывается у сотрудника один раз; права из [tz.actors.md](tz.actors.md) проверяются по ролям;
    - служба ([service.tsv](../zhsr-database/src/main/resources/db/dict/service.tsv)) - свойство роли: у роли не больше одной службы, одну службу могут иметь
      несколько ролей; службы сотрудника - службы его ролей.

#### Депо сотрудника

- **Таблицы:** `usr_depot`.
- **Назначение:** в каком депо работает сотрудник; у каждого сотрудника есть текущее депо.
- **Атрибуты:** сотрудник, депо, период действия записи.
- **Правила:** запись действует с `dbeg` по `dend` (не включая); `dend` пуст - текущая запись. Сотрудник в каждый
  момент работает не больше чем в одном депо.

#### Категория проводника

- **Таблицы:** `usr_category`.
- **Атрибуты:** сотрудник, категория ([category_type.tsv](../zhsr-database/src/main/resources/db/dict/category_type.tsv)), период действия записи.
- **Правила:** запись действует с `dbeg` по `dend` (не включая); `dend` пуст - текущая запись. У сотрудника в каждый
  момент не больше одной категории.
